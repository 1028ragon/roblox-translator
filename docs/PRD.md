이 문서는 만들 제품의 목표와 요구사항을 정의한다. 현재 구현된 기능과 향후 요구사항을 구분하며, 지원 환경·성능 수치·출시 일정이 검증된 사실이라는 의미는 아니다. 확정되지 않은 사항은 마지막 절에서 관리한다.

## 1. 제품 개요

Roblox Translator는 로블록스에서 들리는 외국어 음성을 사용자가 선택한 언어의 자막으로 표시하는 앱이다. 사용자는 프로그램을 실행하고 번역 시작 버튼을 누른 뒤, 게임 화면 위에 표시되는 자막을 보며 대화를 이해한다.

일반 공개 버전은 Python 설치, 터미널 명령, 코드 수정, Azure 계정 및 API 키 발급 없이 사용할 수 있어야 한다. 초기 테스터 버전에서는 검증 속도를 위해 개인 Azure 키 입력을 허용한다.

초기에는 PC 출력 장치의 전체 소리를 캡처한다. 로블록스 소리만 수집하는 기능과 게임 효과음에서 음성채팅만 분리하는 기능은 서로 다른 문제로 취급하며, 첫 버전에서 제공한다고 약속하지 않는다.

## 2. 사용자와 해결할 문제

### 대상 사용자

- 외국어 음성채팅을 이해하기 어려운 한국어 사용 로블록스 이용자
- 개발 도구와 클라우드 서비스 설정에 익숙하지 않은 Windows 사용자
- 초기 버전의 설치·오디오·번역 동작을 검증할 소수의 테스터

### 핵심 문제

| 문제 | 필요한 결과 |
| --- | --- |
| 게임 중 외국어 대화 내용을 이해하기 어렵다. | 게임을 유지하면서 번역 자막을 확인한다. |
| 번역 프로그램 설치와 설정이 복잡하다. | 앱을 설치하고 화면에서 설정한다. |
| 번역이 동작하는지 알기 어렵다. | 준비·실행·오류 상태와 다음 행동을 확인한다. |
| 자막이 입력이나 시야를 방해할 수 있다. | 클릭을 통과시키고 표시 위치·크기를 조정한다. |
| 다른 앱의 소리도 수집될 수 있다. | 캡처 범위와 외부 전송 여부를 알고 시작·중지한다. |

### 핵심 사용자 요구

> 게임을 플레이하는 동안 다른 사람이 하는 말을 한국어 자막으로 이해하고 싶다. 설치 후 복잡한 설정 없이 켜고 끌 수 있어야 한다.

## 3. 목표와 제외 범위

### 목표

1. 실시간 음성을 읽을 수 있는 번역 자막으로 제공한다.
2. 터미널 없이 시작·중지하고 문제 원인을 확인할 수 있게 한다.
3. Python이 없는 PC에서도 실행·설치할 수 있게 한다.
4. 사용자 설정을 저장하고 다음 실행에서 복원한다.
5. 일반 공개 시 개발자의 API 키를 앱에 넣지 않고 이용 권한과 사용량을 관리한다.

### 첫 출시에서 제외

- 크롬 확장 프로그램, 웹앱, 모바일 앱, macOS·Linux 지원
- 사용자의 마이크 음성을 번역해 게임으로 송출하는 기능
- 번역 음성 재생, 음성 합성, 음성 변환
- 로블록스 계정 연동 및 게임 내부 기능 수정
- 화자별 이름 표시, 동시 발화의 완전한 분리
- 음성채팅과 게임 효과음의 완전한 분리
- 언어 자동 감지, 로컬 AI 모델을 이용한 오프라인 번역
- 번역 기록 검색·내보내기, 결제·구독, 자동 업데이트

## 4. 현재 구현 상태

아래 내용은 소스 기준이다. 실제 오디오 장치·Azure 연결·배포 환경에서의 성공을 의미하지 않는다.

| 영역 | 현재 상태 | 제품화에 필요한 작업 |
| --- | --- | --- |
| 실행 | main.py와 실행 연결 코드 분리 | 제어 창에서 실행 관리 |
| 오디오 | 기본 출력 장치의 WASAPI 루프백 캡처 및 PCM 변환 | 장치 선택, 초기화 실패 처리, 종료 안정화 |
| 번역 | Azure SDK의 임시·확정 결과 콜백 연결 | 상태·오류 전달, 세션 수명 관리 |
| 자막 | 클릭 통과 오버레이, 원문·번역 표시 | 임시 자막 만료, 전체 표시 수 제한, 중지 시 초기화 |
| 설정 | config.py 상수 | 설정 화면과 사용자별 저장 |
| 인증 | 프로젝트 .env 또는 환경 변수 읽기 | 테스터용 입력 화면 및 공개용 서버 인증 |
| 테스트 | 녹음·자막 수동 테스트와 기본 회귀 테스트 존재 | 장치·서비스 실패 및 배포 환경 검증 확대 |
| 배포 | 소스 코드 실행 | 실행 파일, 설치·제거, 릴리스 안내 |

## 5. 단계별 출시 범위

| 단계 | 대상 | 제공 범위 | 인증 방식 | 통과 기준 |
| --- | --- | --- | --- | --- |
| A. 테스터용 MVP | 소수 테스터 | 제어 창, 설정, 자막, 실행 파일 | 테스터 개인 Azure 키 입력 | 개발 도구 없는 PC에서 핵심 흐름 검증 |
| B. 설치형 베타 | 설치 경험 검증 참여자 | A + 설치·제거, 바로가기, 버전 표시 | 개인 Azure 키 입력 허용 | 설치·버전 교체·제거 검증 |
| C. 일반 공개 | 일반 Windows 사용자 | B + 로그인, 서버 인증, 이용 한도 | 앱 로그인 후 이용 | 사용자의 API 키 발급 없이 사용 및 운영 비용 통제 |
| D. 후속 개선 | 검증 결과에 따라 결정 | 로블록스 전용 캡처 등 | C와 동일 | 별도 요구사항 및 기술 검증 후 결정 |

A와 B는 사용자 검증을 위한 중간 배포다. 설치와 로그인만으로 사용하는 최종 사용자 경험은 C의 요구사항이다. 단계별 일정은 첫 배포 실험과 API 사용량 측정 후 정한다.

## 6. 주요 사용자 흐름

### 6.1 최초 실행 — 테스터

1. 실행 파일을 다운로드하거나 앱을 설치한다.
2. 앱에서 캡처 범위와 외부 음성 전송 안내를 확인한다.
3. 입력 언어·자막 언어·출력 장치를 선택한다.
4. 개인 Azure 키와 지역을 입력한다.
5. 필요하면 예제 자막으로 글자 크기와 위치를 확인한다.
6. 번역 시작을 누르고 실제 소리로 자막을 확인한다.

### 6.2 최초 실행 — 일반 공개

1. 앱을 설치하고 로그인한다.
2. 캡처·외부 전송 안내와 이용 가능 상태를 확인한다.
3. 언어와 장치를 선택하고 번역을 시작한다.

Azure 키 발급·입력과 .env 편집은 이 흐름에 포함하지 않는다.

### 6.3 게임 중 사용

1. 사용자가 번역 시작을 선택하면 장치와 서비스 연결을 준비한다.
2. 실행 상태를 표시하고 음성에 대한 임시 번역을 자막으로 갱신한다.
3. 확정 결과가 오면 해당 임시 자막을 교체한다.
4. 사용자가 중지를 선택하면 신규 오디오 전송을 중단하고 자원을 정리한다.
5. 남아 있는 자막을 제거하고 대기 상태로 돌아간다.

### 6.4 오류와 재시도

연결 실패, 인증 실패, 장치 사용 불가, 이용 한도 초과를 구분해 표시한다. 실패한 세션을 정리한 뒤 설정 변경 또는 명시적인 재시도를 제공한다. 첫 버전에서는 사용자 동의 없는 자동 재연결을 하지 않는다. 무음 자체를 오류로 표시하지 않는다.

### 7.1 오디오 정책

- 초기 캡처 대상은 선택한 출력 장치의 전체 소리다. 로블록스 실행 여부와 별개로 다른 앱의 소리도 포함될 수 있음을 안내한다.
- 시작 버튼을 누르기 전에는 음성을 수집·전송하지 않는다.
- 중지 요청 시 새로운 오디오의 수집·전송을 중단한다. 이미 외부 서비스에 전달된 데이터의 취소를 보장한다고 표시하지 않는다.
- 선택 장치가 사라지면 번역을 중지하고 재선택을 안내한다. 다른 장치로 조용히 전환하지 않는다.
- 실행 중 언어·장치 변경은 첫 버전에서 제한하고, 중지 후 변경하도록 한다.
- 장치 정지, 전송 실패, 무음을 구분한다.

### 7.2 자막 정책

- 자막은 게임 조작을 방해하지 않도록 클릭을 통과시킨다. 편집은 제어 창과 미리보기에서 수행한다.
- 표시 개수의 단위는 자동 줄바꿈된 화면 줄이 아닌, 원문·번역문을 묶은 하나의 발화 항목이다.
- 임시 항목을 포함해 최대 항목 수를 제한한다. 초과하면 오래된 확정 항목부터 제거한다.
- 확정 자막의 수명은 확정 시점부터, 임시 자막의 수명은 마지막 갱신 시점부터 계산한다.
- 초기 기본값은 최대 3개 항목, 확정 자막 6초, 임시 자막 마지막 갱신 후 6초로 제안한다.
- 원문 표시를 끄면 번역문만 표시한다. 번역문이 없는 결과를 빈 자막으로 누적하지 않는다.
- 기본 표시 대상은 주 모니터 하단이다. 다중 모니터 선택은 후속 개선으로 분리한다.
- 창 모드와 테두리 없는 창 모드를 초기 검증 대상으로 한다. 독점 전체화면 지원은 검증 전 보장하지 않는다.

### 7.3 설정과 인증 정보

- 일반 설정은 앱 설치 폴더와 분리된 사용자별 경로에 저장한다.
- 최초 실행, 설정 손상, 유효하지 않은 값에 대해 기본값과 복구 안내를 제공한다.
- 개인 Azure 키는 초기 테스트에서 현재 앱 실행 동안만 메모리에 보관한다. 재실행 시 다시 입력한다.
- 테스트 앱에서는 화면에 입력한 인증 정보를 우선 사용한다. 개발 실행의 .env·환경 변수 사용은 별도 경로로 구분한다.
- 일반 공개 빌드의 기본 흐름에서는 로컬 .env를 요구하거나 자동으로 인증 수단으로 사용하지 않는다.
- 공개용 세션·로그인 정보의 저장 및 만료 정책은 서버 인증 설계 시 확정한다.

| 실행 중 | 번역 활성 상태 | 중지, 제어 창 확인 |
| 중지 중 | 전송 중단 및 자원 정리 중 | 완료 대기 |
| 오류 | 원인과 해결 방법 | 설정 변경, 정리 완료 후 재시도 |

- 오류가 발생하면 신규 음성 전송을 중단하고 자원을 정리한다. 정리 완료 전 새 시작을 허용하지 않는다.
- 준비 중 중지 요청과 준비 중 창 종료도 지원한다.
- 사용자가 읽는 메시지에는 문제와 다음 행동을 표시하고, API 키·원문 음성·전체 번역문·원시 서버 응답을 노출하지 않는다.
- 로그에는 진단에 필요한 오류 코드와 상태 변경을 기록한다. 복구 불가능한 실패를 실행 중 상태로 남겨두지 않는다.
- 통신·장치 작업이 GUI 스레드의 입력 처리를 막지 않도록 한다.

CPU·메모리·배포 크기·서비스 시간당 비용은 A 단계에서 측정한다. 근거 없는 고정 목표를 두지 않으며, 게임 플레이 영향과 예상 동시 사용자 수를 바탕으로 공개 전 상한을 결정한다.

## 11. 배포와 운영 요구사항

- 초기 검증 환경은 Windows 11 x64로 제안한다. 실제 지원 표기는 배포 검증 후 확정한다.
- 실행 파일에는 필요한 Python 실행 환경과 라이브러리를 포함해 사용자의 별도 설치를 요구하지 않는다.
- A에서는 실행 파일과 의존 파일을 압축해 배포할 수 있다. 단일 exe 형식 자체는 필수 조건이 아니다.
- B에서는 설치·제거와 바로가기를 제공하고 앱과 배포 파일에 버전을 표시한다.
- 새 버전 설치 시 일반 설정을 유지한다. 제거 시 설정 보존·삭제 정책을 명시한다.
- 초기 업데이트는 버전이 표시된 GitHub Release의 새 설치 파일을 사용자가 내려받는 방식으로 제공한다.
- 배포물에 개발자의 .env, API 키, 개인 설정, 녹음 파일, 테스트용 대화 기록을 넣지 않는다.
- 배포 의존성의 재배포 조건과 설치 파일 서명 방식을 검토하고 공개 준비 체크리스트에 기록한다.
- C에서는 서버가 사용자 인증·이용 한도·동시 실행을 판단한다. 앱의 화면 표시만으로 제한을 구현하지 않는다.
- 이미 시작한 세션과 발급된 임시 권한의 만료·중단 방식은 공급자 제약을 검증한 뒤 설계한다. 신규 이용 차단과 활성 세션 종료를 구분한다.
- 사용량 집계는 앱이 측정한 이용 시간과 공급자 청구량이 다를 수 있음을 고려해 정의한다.

## 13. 구현 방향과 의존성

기존 Python·PySide6 구조를 활용한다. 제어 창은 캡처·번역 세션의 상태를 받아 표시하고, 오디오 및 번역 처리는 UI 응답을 막지 않도록 분리한다. 초기에는 Azure 한 곳을 연결하되 공급자별 처리 코드가 자막 화면에 섞이지 않도록 한다. 다른 AI 서비스 지원은 별도 요구사항으로 추가한다.

| 의존성·위험 | 제품 대응 |
| --- | --- |
| 출력 장치와 Windows 환경 차이 | 장치 목록, 재선택 안내, 검증 환경 공개 |
| 게임 효과음·중복 발화·주변 소리 | 첫 버전의 한계를 안내하고 대표 음성으로 평가 |
| 네트워크·번역 서비스 지연 및 장애 | 상태 표시, 안전한 중지, 명시적 재시도 |
| 게임 화면 모드와 오버레이 호환성 | 창 모드 중심 검증, 지원 조건 명시 |
| 실행 파일에 필요한 네이티브 라이브러리 누락 | 개발 도구 없는 PC에서 배포 검증 |
| 사용자 증가에 따른 번역 비용 | 공개 전 사용량 측정, 한도·동시 실행 제한 |
| 로블록스 전용 캡처의 구현 불확실성 | 전체 출력 캡처를 초기 기준으로 삼고 별도 실험 |
