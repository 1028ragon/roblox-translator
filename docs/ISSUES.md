# GitHub 이슈 등록 초안

- 작성일: 2026-11-16
- 기준: [PRD v0.1](PRD.md), [Git Convention](../git%20convention.md)
- 구성: A 14개, B 3개, C 7개, D 1개 — 총 25개
- 문서 상태: 사용자가 GitHub에 등록할 제목·본문 초안

## 등록 방법

1. 아래 각 항목의 제목에서 관리 코드(A-01 등)를 제외한 `[유형] 작업 내용`을 GitHub 이슈 제목으로 사용한다.
2. 해당 항목의 코드 블록 안에 있는 Markdown을 이슈 본문으로 복사한다.
3. 등록한 실제 GitHub 번호를 아래 목록의 관리 코드와 연결해 기록하고, 본문의 선행 작업 코드를 실제 이슈 링크로 바꾼다.
4. 작업은 최신 develop에서 `유형/#실제이슈번호` 브랜치를 생성해 진행한다. 문서 관리 코드를 브랜치 번호로 쓰지 않는다.
5. PR은 Git Convention의 제목·본문 양식을 사용하고 실제 이슈 번호를 연결한다.

관리 코드는 이 문서 안의 식별자이며 GitHub 이슈 번호와 관계없다. 기존 이슈를 교체해도 새 번호를 임의로 가정하지 않는다. 모든 체크박스는 아직 완료하지 않은 작업을 뜻한다. 이 문서는 등록용 초안이며 실제 GitHub 이슈의 생성·삭제 상태를 나타내지 않는다.

## 우선순위와 범위

- P0: 해당 단계의 기반·안전·핵심 동작 또는 출시 검증. 선행 작업부터 진행한다.
- P1: 기반 작업 후 구현할 필수 사용자 기능·문서. 해당 단계 배포 전 완료한다.
- P2: 후속 선택 과제. A·B·C 출시를 막는 조건으로 삼지 않는다.
- A·B·C 단계는 PRD의 누적 출시 기준을 따른다. C의 설계는 A 평가 이후 B와 병행할 수 있지만 일반 공개 검증은 B 완료 후 수행한다.
- A-02 패키징 실험은 초기에, A-14 최종 빌드는 기능 통합 후 수행한다.
- 기능별 단위·실패 경로 테스트는 각 구현 이슈에 포함한다. A-13·B-03·C-07은 통합·품질·배포 검증을 맡는다.
- 이미 완료한 파일 분리, 기본 .gitignore 및 PRD 작성 자체는 다시 구현할 이슈로 포함하지 않는다.
- 다른 번역 AI, 자동 업데이트, 결제, 화자 구분 등 PRD 제외 기능은 이 목록의 출시 범위에 포함하지 않는다.
